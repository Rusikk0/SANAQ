# Настройка Supabase

Пошаговая инструкция для проекта «АвтоЗапчасти — Учёт и касса».

## 1. Создание проекта

1. Войдите на [https://supabase.com](https://supabase.com).
2. **New project** → укажите имя, пароль БД, регион.
3. Дождитесь завершения создания (1–2 минуты).

## 2. Выполнение SQL

1. В панели проекта откройте **SQL Editor**.
2. Создайте запрос **New query**.
3. Скопируйте и выполните **целиком** файл `supabase/01_schema.sql` → **Run**.
4. Создайте второй запрос, выполните `supabase/02_rls.sql` → **Run**.

При ошибках проверьте, что скрипты не выполнялись частично ранее (при необходимости удалите созданные таблицы в Table Editor и повторите).

## 3. Аутентификация (Email + Password)

1. **Authentication** → **Providers** → **Email**.
2. Включите **Email** provider.
3. Для тестирования рекомендуется **отключить** «Confirm email» (Authentication → Providers → Email → Confirm email off), иначе кассиры не смогут войти сразу после приглашения.
4. **Authentication** → **URL Configuration**:
   - **Site URL**: URL вашего GitHub Pages (например `https://username.github.io/repo/`) или `http://localhost:5500` для локальной разработки.
   - **Redirect URLs**: добавьте те же адреса.

## 4. Ключи API для фронтенда

В новой панели Supabase URL и ключ лежат **в разных местах** (это нормально).

### Вариант А — кнопка Connect (проще)

1. На главной страние проекта нажмите **Connect** (или **Project Settings** → подсказка Connect).
2. Вкладка **API Keys** (или App Frameworks → любой фреймворк).
3. Скопируйте:
   - **Project URL** — адрес вида `https://xxxxx.supabase.co`
   - **Publishable key** — ключ вида `sb_publishable_...` (или legacy **anon** `eyJ...`)

### Вариант Б — через настройки

| Что нужно | Где в Dashboard |
|-----------|------------------|
| **Project URL** | **Project Settings** (шестерёнка) → **Data API** → поле URL |
| **Publishable key** | **Project Settings** → **API Keys** → **Publishable key** |

Не используйте на сайте **Secret** / **service_role** — только для сервера.

### Файл `js/config.js`

```javascript
window.AP_CONFIG = {
  SUPABASE_URL: 'https://xxxxx.supabase.co',
  SUPABASE_ANON_KEY: 'sb_publishable_ваш_ключ'  // Publishable = бывший anon
};
```

Имя поля `SUPABASE_ANON_KEY` в коде оставлено для совместимости — вставляйте туда **Publishable key**.

## 5. Первый пользователь и магазин

1. Откройте приложение (`index.html` через локальный сервер или GitHub Pages).
2. **Регистрация** → имя, email, пароль (мин. 6 символов).
3. После входа: **Создать магазин** → введите название.
4. Выберите магазин в списке — откроется касса.

## 6. Приглашение кассира

1. Войдите как **администратор** магазина.
2. Раздел **Кассиры и смены** → **Пригласить кассира**.
3. Укажите имя, email (логин) и временный пароль.
4. Кассир входит тем же email/паролем и выбирает магазин в списке.

> Приглашение создаёт пользователя через `signUp` на отдельном клиенте Supabase, затем добавляет запись в `store_members` с ролью `cashier`.

## 7. Таблицы данных

| Таблица | Назначение |
|---------|------------|
| `stores` | Магазины |
| `store_members` | Участники и роли |
| `profiles` | Имена пользователей |
| `products` | Товары (`store_id`) |
| `categories` | Категории |
| `sales` | Заголовки чеков |
| `sale_items` | Строки чеков |
| `expenses` | Расходы (только admin) |
| `shifts` | Смены |
| `customers` | Клиенты |
| `loyalty_cards` | Карты лояльности |

## 8. Безопасность (RLS)

- Пользователь видит только магазины, где есть запись в `store_members`.
- **Кассир** не видит `expenses` и не может менять товары (кроме остатка при продаже через обновление из приложения — политика `products_update_qty_cashier`).
- **Админ** полный доступ к данным своего магазина.

Проверка: в Table Editor попробуйте запрос от имени authenticated user через SQL с `set request.jwt.claim.sub` — или проще: второй аккаунт кассира не должен видеть чужой `store_id`.

## 9. Синхронизация

- При выборе магазина данные загружаются из Supabase в память (`ApDb`).
- Локальный кэш: `localStorage` ключ `ap_cache_<store_id>`.
- После изменений (товары, продажи и т.д.) данные отправляются в Supabase (`upsert` / `insert`).
- Каждые 30 секунд выполняется фоновое обновление `ApDb.refresh()`.

## 10. Устранение неполадок

| Проблема | Решение |
|----------|---------|
| «Supabase не настроен» | Заполните `js/config.js` |
| Ошибка RLS при insert | Проверьте выполнение `02_rls.sql` и роль пользователя |
| Кассир не входит | Отключите подтверждение email или подтвердите письмо |
| Пустой список магазинов | Создайте магазин или добавьте в `store_members` |
