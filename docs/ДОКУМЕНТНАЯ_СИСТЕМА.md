# Система документов для SANAQ

Разработана полная система управления документами (счета и накладные) для веб-приложения учета товаров и продаж.

## Файлы

- **js/ap-documents.js** — основной сервис для работы с документами
- **index.html** — обновлён UI с новой страницей "Документы" и модальными окнами

## Реализованные функции

### 1. Счет на оплату
- ✅ Автоматическая нумерация (№000001, №000002, и т.д.)
- ✅ Дата создания
- ✅ Таблица товаров с кол-вом, ценой, суммой
- ✅ Общая сумма
- ✅ Статусы: «Ожидает оплаты», «Оплачено», «Отменено»
- ✅ Имя и телефон покупателя (опциональны)
- ✅ Красивый, адаптивный дизайн с логотипом магазина
- ✅ Красный и белый профессиональный стиль

### 2. Накладная на отпуск запасов (форма З-2)
- ✅ Максимально похожа на государственный бланк Казахстана
- ✅ Номер документа и дата
- ✅ Таблица товаров (наименование, ед.изм, кол-во, цена, сумма)

## Использование

### Создание счета на оплату

1. Перейдите на вкладку **"Документы"** в меню
2. Нажмите **"+ Счет на оплату"**
3. Выберите тип:
   - **Ручной ввод**: укажите клиента (опционально) и товары в JSON формате
   - **Из отложенных товаров**: выберите отложенные товары из списка
4. Нажмите **"Создать счет"**
5. Счет появится в списке документов

### Пример JSON товаров для счета

```json
[
  {
    "productCode": "BRK-001",
    "productName": "Тормозные колодки",
    "quantity": 2,
    "unitPrice": 5000,
    "total": 10000
  },
  {
    "productCode": "BRK-002",
    "productName": "Масло моторное",
    "quantity": 1,
    "unitPrice": 3000,
    "total": 3000
  }
]
```

### Создание накладной З-2

1. На вкладке **"Документы"** нажмите **"+ Накладная З-2"**
2. Выберите тип (ручной ввод или из отложенных)
3. Укажите данные и товары
4. Нажмите **"Создать накладную"**

### Просмотр и действия с документом

1. В списке документов нажмите **"👁️ Просмотр"**
2. Откроется модальное окно с документом
3. Доступные действия:
   - **🖨️ Печать** — откроется окно печати браузера
   - **📥 Excel** — скачать документ в формате .xlsx
   - **✓ Оплачено** / **← Вернуть** — изменить статус
   - **🗑️ Удалить** — удалить документ из списка

## Технические детали

### Суфлиры хранения

Все документы сохраняются в Supabase в таблицах:
- **documents** — основная информация о документах
- **document_items** — строки документов (товары)

### Синхронизация

- Документы автоматически синхронизируются с Supabase
- Поддержка офлайн-режима с локальным кешированием
- Ежедневный автосинк при подключении к интернету
- Резервное копирование в localStorage

### API

Основной API находится в `window.ApDocuments`:

```javascript
// Создание документа
ApDocuments.createDocument('invoice', items, customerName, customerPhone);

// Создание из отложенных товаров
ApDocuments.createDocumentFromDeferred('invoice', deferredIds);

// Получение документа
var doc = ApDocuments.getDocument(docId);

// Обновление статуса
ApDocuments.updateDocumentStatus(docId, 'paid');

// Экспорт в Excel
ApDocuments.exportDocumentExcel(doc);

// HTML-рендеринг
var html = ApDocuments.buildInvoiceHTML(doc);
var html = ApDocuments.buildZ2HTML(doc);
```

## SQL запросы для Supabase

Все необходимые таблицы уже созданы. Если нужно переустановить схему:

```sql
-- Таблица документов
CREATE TABLE IF NOT EXISTS public.documents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  store_id UUID NOT NULL REFERENCES public.stores(id) ON DELETE CASCADE,
  doc_type TEXT NOT NULL CHECK (doc_type IN ('invoice','z2')),
  doc_number TEXT NOT NULL DEFAULT lpad(nextval('public.document_number_seq')::text, 6, '0'),
  status TEXT NOT NULL DEFAULT 'pending',
  customer_name TEXT NOT NULL DEFAULT '',
  customer_phone TEXT NOT NULL DEFAULT '',
  total NUMERIC(14, 2) NOT NULL DEFAULT 0,
  created_by UUID REFERENCES auth.users(id),
  created_by_name TEXT NOT NULL DEFAULT '',
  document_date TIMESTAMPTZ NOT NULL DEFAULT now(),
  meta JSONB,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Таблица строк документов
CREATE TABLE IF NOT EXISTS public.document_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  store_id UUID NOT NULL REFERENCES public.stores(id) ON DELETE CASCADE,
  document_id UUID NOT NULL REFERENCES public.documents(id) ON DELETE CASCADE,
  product_id UUID REFERENCES public.products(id) ON DELETE SET NULL,
  product_code TEXT NOT NULL DEFAULT '',
  product_name TEXT NOT NULL DEFAULT '',
  unit TEXT NOT NULL DEFAULT 'шт',
  quantity NUMERIC(12, 2) NOT NULL DEFAULT 1,
  unit_price NUMERIC(14, 2) NOT NULL DEFAULT 0,
  total NUMERIC(14, 2) NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Индексы
CREATE INDEX IF NOT EXISTS idx_documents_store_date ON public.documents(store_id, document_date DESC);
CREATE INDEX IF NOT EXISTS idx_document_items_document ON public.document_items(document_id);
CREATE INDEX IF NOT EXISTS idx_document_items_store ON public.document_items(store_id);
```

## Интеграция с отложенными товарами

После создания документа из отложенных товаров рекомендуется:
1. Перевести отложенные товары в статус "completed" (оплачено)
2. Или отменить их, если документ был создан по ошибке

Это можно сделать через интерфейс отложенных товаров или программно.
