# Часть 4. Включить сайт на GitHub Pages (подробно)

Эта инструкция — **только про шаг 4**: как из загруженных файлов сделать **рабочий сайт в интернете** с постоянной ссылкой.

**До этого** вы уже должны были:
- зарегистрироваться на GitHub (часть 1);
- создать репозиторий, например `autozapchasti` (часть 2);
- загрузить файлы: `index.html`, папка `js` с `config.js` и остальное (часть 3).

Если файлов ещё нет — сначала выполните части 1–3 из файла `КАК_ВЫЛОЖИТЬ_САЙТ.md`.

---

## Что вы получите в конце

Рабочая ссылка вида:

```text
https://ВАШ-ЛОГИН.github.io/autozapchasti/
```

- **ВАШ-ЛОГИН** — имя пользователя GitHub (видно в правом верхнем углу на github.com).
- **autozapchasti** — имя репозитория (если назвали иначе — подставьте своё имя).

Эту ссылку вы вставляете в браузер **всегда**, когда хотите открыть кассу. CMD больше не нужен.

---

## Шаг 4.1. Откройте свой репозиторий

1. Зайдите на [https://github.com](https://github.com) и войдите в аккаунт.
2. Вверху справа нажмите на **аватар** → **Your repositories** (Ваши репозитории).
3. Нажмите на репозиторий **`autozapchasti`** (или как вы его назвали).

Вы должны видеть список файлов, среди них:
- `index.html`
- папка `js`
- возможно папки `docs`, `supabase`

Если **`index.html` нет в корне** (а лежит внутри папки `095`) — сайт не откроется. Тогда в корне репозитория должны быть файлы **напрямую**, не вложенная папка `095`. Исправьте загрузку (часть 3) и вернитесь сюда.

---

## Шаг 4.2. Зайдите в настройки Pages

1. На странице репозитория вверху есть вкладки: **Code**, **Issues**, **Pull requests**…
2. Нажмите вкладку **Settings** (Настройки).  
   - Если не видите **Settings** — вы не владелец репозитория; нужен свой аккаунт и свой репозиторий.
3. В **левом меню** прокрутите вниз до раздела **Code and automation**.
4. Нажмите **Pages**.

---

## Шаг 4.3. Настройте публикацию

На странице **GitHub Pages** найдите блок **Build and deployment** (Сборка и развёртывание).

### Поле «Source» (Источник)

1. Откройте выпадающий список **Source**.
2. Выберите **Deploy from a branch** (Развернуть из ветки).  
   - Не выбирайте «GitHub Actions», если вы не настраивали workflow специально — для начала проще **branch**.

### Поле «Branch» (Ветка)

Под Source появятся два выпадающих списка:

1. **Первый список (ветка):** выберите **`main`**.  
   - Если есть только **`master`** — выберите **master**.
2. **Второй список (папка):** выберите **`/ (root)`** — это корень репозитория, где лежит `index.html`.
3. Нажмите кнопку **Save** (Сохранить).

---

## Шаг 4.4. Дождитесь публикации

После Save страница обновится.

1. Подождите **от 1 до 10 минут** (обычно 2–5 минут).
2. Обновите страницу **Settings → Pages** (F5).
3. Вверху появится зелёная рамка или текст вроде:

   **«Your site is live at …»**  
   **«Ваш сайт опубликован по адресу …»**

4. Нажмите на эту **синюю ссылку** — откроется ваш сайт «АвтоЗапчасти».

### Если написано «Site building» / «Check back soon»

Это нормально — сайт ещё собирается. Подождите 3–5 минут и обновите страницу.

### Если ошибка «Branch not found»

Значит файлы не закоммичены в ветку `main`:

1. Вкладка **Code** репозитория.
2. Слева над списком файлов посмотрите название ветки (например `main`).
3. В **Pages** выберите **ту же** ветку.

---

## Шаг 4.5. Проверьте сайт в браузере

1. Скопируйте ссылку из GitHub Pages, например:

   ```text
   https://ivanov.github.io/autozapchasti/
   ```

2. Откройте **новую вкладку** в Chrome или Edge.
3. Вставьте ссылку в **адресную строку** (не в поиск Google) → Enter.

**Должно открыться:**
- тёмный экран входа;
- заголовок **АвтоЗапчасти**;
- кнопки входа / регистрации.

**Не должно быть:**
- жёлтого предупреждения «откройте через файл» (если открыли по https-ссылке GitHub);
- пустой белой страницы.

### Если страница пустая или 404

| Причина | Что сделать |
|---------|-------------|
| Прошло меньше 5 минут | Подождите, обновите F5 |
| `index.html` не в корне репозитория | Перезагрузите файлы так, чтобы `index.html` был сразу в корне |
| Неверное имя в ссылке | Ссылка = `логин.github.io/ИМЯ_РЕПОЗИТОРИЯ/` |
| Старый кэш | Ctrl + F5 |

### Если «404 File not found» от GitHub

Часто репозиторий называется иначе. Правильный формат:

```text
https://ЛОГИН.github.io/ТОЧНОЕ_ИМЯ_РЕПОЗИТОРИЯ/
```

Имя репозитория смотрите под заголовком на вкладке **Code** (например `autozapchasti`).

---

## Шаг 4.6. Сохраните ссылку

1. В браузере: **звёздочка** → добавить в закладки «АвтоЗапчасти».
2. Запишите ссылку в блокнот — это ваш **постоянный адрес кассы**.

Дальше по инструкции проекта идёт **часть 5** — настроить Supabase (Site URL и Redirect URLs) **на эту же ссылку**. Без этого вход может не работать.

Кратко часть 5:

1. [supabase.com/dashboard](https://supabase.com/dashboard) → ваш проект.
2. **Authentication** → **URL Configuration**.
3. **Site URL** = ваша ссылка GitHub Pages (с `https://` и со слэшем в конце).
4. **Redirect URLs** → **Add URL** → та же ссылка (можно добавить второй вариант без слэша в конце).
5. **Save**.

---

## Два варианта интерфейса GitHub (если не находите пункты)

### Вариант А — классический (ветка main)

Как описано выше: **Settings → Pages → Deploy from a branch → main → / (root) → Save**.

### Вариант Б — «GitHub Actions» уже выбран

Если в Source уже стоит **GitHub Actions** и сайт опубликован — ссылка всё равно будет на вкладке **Pages** сверху. Просто дождитесь зелёного статуса и откройте ссылку.

В проекте есть файл `.github/workflows/pages.yml` — при push в `main` сайт может обновляться автоматически. Для первого раза достаточно **Deploy from a branch**.

## Чеклист: часть 4 выполнена?

Отметьте себе:

- [ ] **Settings → Pages → Save** с веткой `main` и папкой `/ (root)`

## Частые вопросы

**Нужен ли CMD после части 4?**  
Нет. Только ссылка GitHub Pages.

**Можно ли открывать index.html с рабочего стола?**  
Нет. Только https-ссылка с GitHub.

**Сайт открылся, но ошибка входа / Supabase**  
Выполните часть 5 (URL в Supabase) и проверьте `js/config.js` на GitHub (должны быть ваш URL и Publishable key).

**Как обновить сайт после правок?**  
Снова загрузите изменённые файлы в репозиторий (Upload files) → через 1–3 минуты сайт обновится.
